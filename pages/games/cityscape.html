Overview

CityScape – Mini City Builder is a grid-based city building simulation with a switchable 3D exploration mode. Players place buildings from categories (Residential, Industrial, Utility, Services, Decoration), draw roads with auto-tiling, manage a simple economy, and can walk through their city in Explore Mode with NPC dialogue.

Your Contribution

As the sole developer, I built all systems from scratch:

  • Grid System (Core): Created a 2D array of GridCell objects representing the world grid, providing world-to-grid coordinate conversion, occupancy tracking, and visualization. Event-driven design keeps downstream systems decoupled.
  • Building Placement: Implemented a full ghost-preview workflow, validate, place, and delete functionality. The BuildingPlacer orchestrates raycasting, transparent ghosts, highlighted footprint quads, and legality checks.
  • Road Placement with Auto-Tiling: Built a click-drag road drawing system. Roads automatically select their tile variant (straight, corner, T-junction, 4-way, dead-end) based on neighbor connections, using ghost pool reuse to prevent excessive GC during drag preview.
  • Economy Manager: Tracks currency, income, expenses, and building costs. Fully event-driven, subscribing to building placement and removal events.
  • Save / Load System: Designed a 3-slot persistent save/load system with auto-save that serializes entire city states (grid data, placed buildings, roads, economy) to JSON.
  • Explore Mode: Created a seamless toggle between a top-down Build Mode and a 3D walk-around Explore Mode. Coordinated camera, input, UI, and NPC systems.

Technical Deep-Dive

Road Auto-Tiling via Neighbor Bitmask

When placing roads, each tile must automatically choose the correct visual variant (straight, corner, T-junction, 4-way, dead-end) and rotation based on which of its 4 neighbors are also roads. RoadTileSelector.cs queries the road dictionary for all 4 cardinal neighbors, builds a connection pattern, and uses a lookup to determine the correct prefab variant and Y-axis rotation. Drag-draw preview uses a ghost pool so no GC allocations occur during cursor movement.

3-Slot JSON Save System with Auto-Save

Persisting an entire city — potentially hundreds of placed objects with grid coordinates, building types, and road networks — across sessions, with 3 independent slots and metadata. SaveManager serializes GameSaveData to JSON via JsonUtility. Saves go to persistentDataPath/Saves/. A coroutine fires auto-save on a timed interval. Slot metadata (timestamp, city name) is stored separately for the save slot UI. 

// SaveManager.cs
public const int MaxSlots = 3;

Postmortem / Lessons Learned

What went well

  • Modular system design paid off. Building the grid system, placement, road placer, and economy as separate decoupled classes (communicating via C# events) meant I could develop and test each independently without breaking the others.
  • Road auto-tiling worked first time. The neighbor-bitmask approach for choosing road tile variants was the most complex algorithm in the project, and it worked correctly from the first full playthrough — validating the upfront planning invested before writing code.

What I'd do differently

  • Split the large classes earlier. BuildingPlacer.cs (552 lines) and RoadPlacer.cs (652 lines) became difficult to navigate. I'd extract the drag-preview and ghost-pool logic into their own classes from day one rather than letting them grow inside the placer.
  • Add version control from the start of each feature, not in weekly batches. With only 7 commits across 3 weeks, individual features aren't traceable in git history. Committing at feature-level boundaries would make the development story much clearer.
