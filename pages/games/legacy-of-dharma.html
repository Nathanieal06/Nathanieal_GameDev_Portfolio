Overview

Legacy of Dharma is a third-person action/adventure game featuring a dynamic two-state stance system that seamlessly bridges exploration and intense combat. The core hook lies in its multi-hit combo sword & shield mechanics and integrated horse riding, providing players with a AAA "snappy" feel that perfectly blends responsive movement with weighty, animation-driven strikes.

Your Contribution

As the Lead Programmer for this team project, my primary task was to architect and implement the core gameplay mechanics from scratch, specifically focusing on the player controller:

  • Third-Person Player Controller: Built a custom state-machine approach driving Unity's CharacterController, reading from the new InputSystem. Added "Coyote Time" for precise jumping, i-frames during dodge rolls, and dynamic speed interpolation to blend script-driven physics with root-motion animation.
  • Horse Riding & Mount System: Developed a seamless mount/dismount system using raycast detection. Managed complex parent/child transform relationships with LateUpdate snapping and Inverse Kinematics (IK) to dynamically lock the player's hands to the horse's moving reins without visual jitter.
  • Combat & Damage Framework: Implemented a combo system that queues attacks based on input timing windows. Used event-driven weapon colliders that activate strictly during specific animation frames, and created dynamic AI reactions like stopping distance alterations when the player blocks.
  • Enemy AI System (NavMesh): Abstracted an EnemyBase class to govern AI states (Idle, Patrol, Attack, Hit, Death) using Unity's NavMeshAgent. Built derived variants like BossEnemy and PatrolEnemy with logic for chasing, staggering, and dropping probabilistic loot.

Technical Deep-Dive

Hybrid Root Motion Combat System

Standard CharacterController script-driven movement feels floaty during sword swings, but relying entirely on root motion makes basic exploration feel sluggish and unresponsive. To solve this, I decoupled the movement logic. During exploration, the script drives the CharacterController via WASD math. During an attack, script movement is suppressed, and OnAnimatorMove injects the animation's exact root displacement into the CharacterController. This keeps collisions active while the animation drives the distance, resulting in a AAA "snappy" feel that blends responsive movement with weighty combat strikes. 

private void OnAnimatorMove()
{
    if (_isDead || _controller == null || !_controller.enabled) return;

    if (_isAttacking)
    {
        // Apply animation's root-motion displacement so attacks step forward naturally
        Vector3 rootDelta = _animator.deltaPosition;
        rootDelta.y = _verticalVelocity * Time.deltaTime; // Maintain gravity
        _controller.Move(rootDelta);
        transform.rotation *= _animator.deltaRotation;
        
        // Track targeted enemy dynamically mid-swing
        if (_targetingSystem != null && _targetingSystem.IsTargeting) { /* ... */ }
    }
}

Robust Mount/Dismount & IK Reins System

When transitioning a player onto a moving horse, standard animation root motion often causes the player to drift away from the saddle, and hands rarely align with the reins. During mounting, the player's CharacterController is disabled, and they are parented to the horse. In LateUpdate, the player's local position/rotation is hard-locked to zero to prevent drift. Additionally, Unity's Avatar IK system forces the player's hands to track the horse's moving rein bones. 

void LateUpdate()
{
    if (isMounted && !isTransitioning)
    {
        // Lock player exactly to the saddle to prevent root motion drift
        transform.localPosition = Vector3.zero;
        
        // Snap the horse's reins directly to the player's hands via IK targets
        if (snapReinsToHands && currentHorse != null && playerAnimator.isHuman)
        {
            Transform leftHand = playerAnimator.GetBoneTransform(HumanBodyBones.LeftHand);
            if (leftHand != null) currentHorse.leftReinBone.position = leftHand.position;
        }
    }
}

Postmortem / Lessons Learned

What went well

  • Hybrid Controller Architecture: Decoupling script-driven locomotion from animation-driven root motion in the ThirdPersonController was a major success. By overriding OnAnimatorMove exclusively during combat, I successfully combined highly responsive exploration controls with weighty, grounded sword strikes that don't slide across the floor.
  • Complex Hierarchy & IK Management: The horse riding system required orchestrating multiple overlapping systems: temporarily disabling the Character Controller, managing dynamic transform parenting, and interpolating Inverse Kinematics (IK) for the reins. The resulting system transitions smoothly without visual jitter, demonstrating a strong grasp of Unity's execution order (e.g., enforcing local coordinate locking in LateUpdate).
  • Dynamic Combat Framework: Centralizing the combat hit detection through overlapping bounds in WeaponDamage.cs and abstracting AI behavior in EnemyBase.cs made the combat loop highly modular. Features like block detection automatically adjusting the AI's stopping distance and specialized boss knockbacks were implemented cleanly without tightly coupling or bloating the scripts.

What I'd do differently

  • Better Architecture Planning to Reduce Dead Code: The project contains redundant legacy scripts like EnemyHealth.cs, which holds an unfinished TODO for death logic, despite EnemyBase.cs ultimately taking over all health and loot functionality. In the future, I will outline my abstract base classes more thoroughly before prototyping to avoid leaving orphaned scripts in the final architecture.
  • Commit History & Scope Management: The Git history for this project consists of an "Initial check-in" followed by four consecutive commits all simply titled "Final Version". This reflects the frantic rush of applying late-stage bug fixes right before the deadline rather than maintaining steady version control. Next time, I will adopt a strict branch-per-feature workflow with descriptive, atomic commits to ease deployment stress.
  • Adopt Automated Testing: Because the project relies entirely on manual playtesting, verifying changes to the complex character state machine (combos, blocking, dodging, riding) became incredibly time-consuming and brittle. Implementing basic unit tests and adopting Test-Driven Development (TDD) for core state mechanics would significantly reduce manual QA overhead.
  • Object Pooling for Late-Stage Pivots: Late in development, I pivoted to leaving enemy corpses in the world instead of despawning them (leaving commented-out Destroy(gameObject, 3f) calls in the code). While this improved immersion, I should have implemented an Object Pooling system to handle it, as endlessly persisting dead GameObjects can eventually bloat memory and clutter NavMesh pathing.
