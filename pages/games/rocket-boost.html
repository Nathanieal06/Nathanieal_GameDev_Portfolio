Overview

Rocket Boost is a physics-based 3D platformer where the player controls a rocket that must thrust and rotate to reach landing pads while avoiding obstacles. Crashing restarts the level, landing on the pad advances to the next, and oscillating hazards add difficulty along the way.

Your Contribution

Based on course material, I built the following core systems:

  • Physics-Based Movement: Implemented thrust-based rocket movement utilizing a hybrid model — applying physical Rigidbody force for momentum and drift while retaining direct transform manipulation for crisp, responsive rotation.
  • Collision Handler: Developed a tag-based collision state machine that distinguishes between ignoring friendly objects, advancing on landing pads, or triggering a crash.
  • Oscillating Obstacles: Created moving hazards utilizing sine-based calculations to seamlessly move objects between points each frame.
  • VFX Systems: Integrated thrust particle exhaust and impact explosion VFX based on input and physics triggers.

Technical Deep-Dive

Physics Thrust + Transform Rotation Hybrid

A rocket needs to feel physically heavy and responsive. Pure physics for both movement and rotation feels uncontrollable; a character controller feels too direct. Rigidbody.AddRelativeForce() governs thrust so momentum and drift behave physically. Rotation is applied directly to transform (not physics) so turning feels crisp and immediately responsive while thrust remains realistic. This hybrid is a common pattern for satisfying spacecraft controls.

Tag-Based Collision State Machine

The rocket needs three collision behaviors: ignore friendly objects, advance on landing pad, crash on everything else. CollisionHandler.cs branches in OnCollisionEnter on collision.gameObject.tag — "Friendly" = ignore, "Finish" = load next scene, everything else = crash + respawn. It's minimal, readable, and does exactly one thing.

Postmortem / Lessons Learned

What went well

  • Physics balance: The hybrid movement model felt much better than purely physics-driven rotation.
  • Level flow: Simple mechanics allowed for engaging level design.

What I'd do differently

  • Better checkpoints: Add intermediate checkpoints to larger levels.
