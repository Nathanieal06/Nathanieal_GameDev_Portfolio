Royal Run

Unity C# Endless Runner
Play Now GitHub Repo
Role Sole Developer
Team Size 1
Duration Game Jam
Engine Unity 6 (6000.3.11f1)
Platform PC (Windows)
Status Completed Prototype

Overview

Royal Run is a 3D endless runner and an earlier predecessor to the LastStride project. The player character runs forward automatically through procedurally generated chunks, dodges obstacles across 3 lanes, collects coins and apples, and survives as long as possible.

Your Contribution

I built the foundational endless runner framework that would later scale into LastStride:

  • Player Controller (Runner): Built automatic forward movement with 3-lane switching, jump capabilities, and rigid collision handling. Integrated a CameraController to reliably trail the player.
  • Procedural Level Generator: Managed an endless chunk lifecycle, generating fixed-length level segments ahead of the player and destroying passed ones behind to conserve memory.
  • Base Class Pickup Inheritance: Used inheritance logic for collectibles (Coins, Apples) to share trigger overlap behaviors but branch off unique score/reward logic.
  • Checkpoint System: Designed checkpoints to mark progress milestones in the run.

Media & Iteration

Technical Deep-Dive

Chunk-Based Infinite World

An endless runner needs an infinite world without consuming infinite memory. The LevelGenerator maintains a sliding window of active chunks. As the player passes each chunk, it's destroyed and a new one spawns ahead. Fixed chunk length ensures consistent density.

Physics Material for Runner Feel

Custom PhysicsMaterial assets with configurable dynamicFriction, staticFriction, and bounciness were applied to the ground and player collider for precise physical feel tuning, massively improving the snappiness of the lane switches compared to default Unity physics values.

Base Class Pickup Inheritance

Coins and apples share the same "player walks through → reward" logic but differ in what reward they grant. The Pickup base class handles the trigger detection and player reference lookup. Coin and Apple extend it and override only the reward logic — yielding zero code duplication.

Postmortem / Lessons Learned

What went well

  • Infinite generation: The chunk-based generation works seamlessly and without lag spikes, providing a true endless experience.
  • Code organization: Utilizing inheritance for pickups kept the codebase small and extensible.

What I'd do differently

  • Procedural curves: The path is perfectly straight. Adding slight curves or verticality to the chunks would make the endless runner feel more dynamic.
