Overview

Sharp Shooter is a 3D third-person shooter where the player navigates a level, switches between weapons using a ScriptableObject-based weapon system, fights enemies (robots and turrets spawned from gates), and tracks ammo.

Your Contribution

As the sole developer, I architected the core combat loops and Enemy AI:

  • ScriptableObject Weapon System: Developed a pure data-driven weapon architecture where weapon stats (damage, fire rate, ammo) are serialized on ScriptableObjects, completely decoupling logic from data so no code changes are required for new weapons.
  • Enemy AI & Spawners: Implemented AI-driven robots with detection ranges and stationary turrets that track and fire at the player, as well as SpawnGates for interval-based enemy spawning.
  • Projectiles & Combat Feedback: Handled physics-based projectiles with explosion VFX on impact.
  • Damage Popup Floats: Built a satisfying floating damage number system that spawns TextMeshPro world-space text, rising from the hit position and fading out.

Media & Iteration

Technical Deep-Dive

ScriptableObject-Based Weapon Architecture

In a shooter, adding new weapons usually means duplicating code or hard-coding stats into scripts. I used WeaponSO to define all weapon stats as serialized fields on a ScriptableObject. ActiveWeapon reads the currently equipped SO's data for all firing logic. New weapons are created as .asset files — no code changes needed. Proper use of Unity's ScriptableObject pattern demonstrates an understanding of data-driven design that scales to large production games.

Floating Damage Numbers

Combat needs visceral feedback — the player needs to feel like hits are connecting. DamagePopup.cs instantiates a world-space TextMeshPro canvas at the hit position, applies upward velocity to a Vector3 offset over time, and fades Color.a to 0 before destroying the object. This minor addition makes combat feel dramatically more satisfying rather than silent stat changes.

Postmortem / Lessons Learned

What went well

  • The ScriptableObject weapon system was the right call. Defining weapons as data assets meant tweaking stats (damage, fire rate, ammo) never required touching code — pure inspector edits. It's a pattern I've carried into later projects for similar data.
  • Floating damage numbers had a disproportionate impact on game feel. Adding DamagePopup.cs was a few hours of work, but it made combat feel dramatically more satisfying — hits felt real and impactful rather than silent stat changes.

What I'd do differently

  • Implement the enemy death logic. EnemyHealth.cs has a // TODO: Add death logic here comment — death is currently not implemented. A proper death state (animation, loot drop, despawn) should have been part of the enemy system from the beginning.
  • Upgrade to Cinemachine 3.x. This project uses Cinemachine 2.10.6 while all later projects use 3.x. Learning the new API would have been a worthwhile investment — the targeting and follow camera features in 3.x are significantly better, and migrating this project now would mean updating a lot of scene references.
