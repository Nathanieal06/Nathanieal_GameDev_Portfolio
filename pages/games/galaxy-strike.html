Galaxy Strike

Unity C# Space Shooter
Play Now GitHub Repo
Role Sole Developer
Team Size 1
Engine Unity 6 (6000.3.11f1)
Platform PC (Windows)
Status Completed Prototype

Overview

Galaxy Strike is a fast-paced space shooter. The player pilots a spacecraft, moves within screen bounds with banking/pitching visual feedback, fires projectiles at enemies, and tracks score. The project leverages Unity's High Definition Render Pipeline (HDRP) and ShaderGraph for high-quality space visuals, along with Timeline sequences for cinematic cutscenes.

Your Contribution

As the sole developer, I implemented all core gameplay systems:

  • Player Ship Movement: Created a 2D-style space ship movement clamped within screen bounds, featuring smooth pitch and roll banking based on player input for a responsive feel.
  • Weapon / Shooting System: Handled input-driven projectile firing with configurable fire rates.
  • Enemy System & Collision: Implemented lightweight enemy logic and handled collisions between the player, bullets, and enemies.
  • Timeline Cutscenes: Integrated an intro sequence using Unity Timeline with activation/animation tracks to sequence camera moves, dialogue, and enemy spawns without hard-coding timings.
  • Graphics Pipeline: Utilized HDRP, ShaderGraph, and Post Processing (bloom, chromatic aberration) to achieve high-quality space aesthetics.

Technical Deep-Dive

Banking Ship Movement with Clamped Bounds

A space shooter needs the ship to feel physically responsive — rolling when moving left/right, pitching when moving up/down — while staying within screen boundaries. Movement and rotation are processed as two completely separate concerns. Local position is clamped to configurable X/Y ranges. Rotation uses Quaternion.Lerp with independent pitch and roll factors, making the banking feel smooth and fully tunable in the inspector. 

// PlayerMovement.cs
void ProcessTransform() {
    float xRaw = transform.localPosition.x + movement.x * controlSpeed * Time.deltaTime;
    float yRaw = transform.localPosition.y + movement.y * controlSpeed * Time.deltaTime;
    transform.localPosition = new Vector3(
        Mathf.Clamp(xRaw, -xClampRange, xClampRange),
        Mathf.Clamp(yRaw, -yClampRange, yClampRange), 0f);
}

void ProcessRotation() {
    float pitch = -controlFactorPitch * movement.y;
    float roll  = -controlRollFactor  * movement.x;
    transform.localRotation = Quaternion.Lerp(
        transform.localRotation, Quaternion.Euler(pitch, 0f, roll),
        rotationSpeed * Time.deltaTime);
}

HDRP for Space Visuals & Timeline Sequences

Achieving high-quality space visuals required using HDRP along with ShaderGraph for custom spaceship/energy shaders and the Post Processing stack for volumetric lighting and bloom. Additionally, integrating a cutscene without hard-coding timings in script was solved using Unity Timeline, allowing visual sequencing of camera moves, dialogue, and enemy spawns with zero code required for the sequence itself.

Postmortem / Lessons Learned

What went well

  • The banking/pitch movement felt great immediately. Separating translation and rotation into two independent methods made it easy to tune each independently without breaking the other — the ship feels alive and responsive.
  • HDRP delivered the visual quality I wanted. The volumetric lighting and post-processing bloom gave the game a polished space atmosphere that would have been much harder to achieve with the standard pipeline.

What I'd do differently

  • Set up version control from the beginning. Not having git history means there's no record of the iteration process — I can't look back at how the enemy system evolved or when the Timeline sequence was added.
  • Add a difficulty progression system. The game currently has no enemy scaling or wave system. I'd plan a configurable wave spawner from the start rather than treating it as something to add later.
